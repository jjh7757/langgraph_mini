## 의존 방향

```
api / cli → agent → orchestration → (account | card | billing) → 각자 repository → domain
```

- `orchestration`은 `account`/`card`/`billing`의 서비스 protocol만 알고 구현체는 모름 (생성자 주입)
- `agent`는 `orchestration`만 호출 — 도메인 서비스를 직접 호출하지 않음 (승인 없이 실행되는 경로를 원천 차단)
- `api`는 `agent.graph.build_graph()`/`agent.wiring.build_orchestration_sql()`만 조립하고
  씀 — `cli.py`와 완전히 같은 패턴, 저장소 구현체만 다름
- `db.postgres`는 각 `*_repository_sql.py`가 개별적으로 의존(직접 커넥션을 안 들고, 호출
  시점에 `current_connection()`으로 조회)

## 초안에서 바뀐 것 — `db/` 설계

**초안(`5_아키텍처_도메인저장계층_초안.svg`, `7_아키텍처_저장소_확장후_Postgres.svg`)**: 공유
`PgSession`을 각 `Sql*Repository`가 생성자로 주입받는 방식으로 그려져 있었다.

**실제 구현**: `Sql*Repository`는 생성자 인자가 없고(`MemoryAccountRepository()`와 똑같은
모양), 메서드 안에서 `db.postgres.current_connection()`으로 "현재 요청의 트랜잭션"을 찾아
쓴다. 그 트랜잭션은 API 레이어가 `with request_transaction(pool):` 블록으로 요청(에이전트
한 턴) 단위로 열고 닫는다.

**바뀐 이유**: `agent/graph.py`의 `InMemorySaver` 체크포인터는 그래프 객체 하나가 프로세스
내내 유지돼야 같은 대화의 여러 HTTP 요청에 걸쳐 문맥이 이어진다(CLI가 그래프를 한 번만 만들어
REPL 내내 재사용하는 것과 동일한 이유). 그런데 DB 쓰기는 요청 하나 단위로 트랜잭션이 걸려야
`transfer()`의 계좌 2개 저장, `pay_bills()`의 청구서별 3저장 같은 다중 저장이 원자적으로
처리된다. 초안대로 `Sql*Repository`가 생성자로 세션/커넥션을 받으면, 그래프도 요청마다 새로
만들어야 해서 체크포인터가 매번 리셋되는 문제와 충돌한다. contextvar로 "현재 커넥션"을
간접 주입하는 방식으로 이 충돌을 해결했다 — 그래프·orchestration·repository 객체는 전부
프로세스 시작 시 한 번만 조립되고, 실제 커넥션만 요청마다 바뀐다.

동시성 제어도 초안엔 없던 내용인데 실제로 추가했다: 단건 조회(`find_by_id` 계열)는 전부
`SELECT ... FOR UPDATE`로 잠근다. 이유는 `진행상황.md`의 "핵심 결정 사항" 참고.

## 실행 중 발견한 버그 — 코드에 반영됨

실제 Gemini API 키로 돌려보고, 실제 AWS 서버에 배포해보면서 설계 문서만으로는 안 드러났던
문제 몇 개를 발견해 전부 코드로 고쳤다(자세한 경위는 `진행상황.md` 참고):

- **`thinking_budget` 기본값(-1, 동적)** — tool 22개+system prompt를 한꺼번에 bind하면 모델이
  thinking에 예산을 전부 써버리고 tool 호출도 텍스트도 없이 끝나버림. `graph.py`를 부르는
  쪽(`cli.py`/`api/app.py`)에서 `thinking_budget=1024`로 고정
- **시스템 프롬프트 — 중복 확인·별명 해석** — 실행형 요청에 정보가 다 있어도 tool 호출 전에
  채팅으로 먼저 되묻거나, 별명("생활비")을 ID로 못 바꿔 계좌를 못 찾는 문제. "정보 있으면 바로
  tool 호출, 별명은 조회 tool로 먼저 ID화" 규칙 + few-shot 예시로 해결
- **`api/app.py`가 `GOOGLE_API_KEY` 없으면 죽음** — `cli.py`는 이미 가드가 있는데 API 쪽엔
  없었음. 키 없으면 헬스체크는 살려두고 채팅만 503
- **`docker-compose.yml` 헬스체크가 `wget`을 쓰는데 베이스 이미지엔 없음** — Python 기반
  헬스체크로 교체(서버 전용 파일이라 레포에는 없음)
- **`REDIS_URL` 조립 시 공유 비밀번호를 URL-인코딩 안 함** — 비밀번호에 포함된 `/`, `+`, `=`
  때문에 redis-py의 URL 파서가 host:port를 잘못 쪼갬. `urllib.parse.quote()`로 인코딩
- **`deploy.yml`의 브랜치가 템플릿 그대로 `master`** — 이 저장소 기본 브랜치는 `main`이라
  고치기 전까지 파이프라인이 아예 안 돌고 있었음
- **챗봇 답변이 가끔 `[object Object]`로 새어나감** — `AIMessage.content`가 항상 문자열은
  아니고, Gemini가 가끔 `[{"type": "text", "text": "..."}]` 같은 다중 파트 리스트로 반환할
  때가 있었음. `agent/graph.py`의 `extract_reply_text()`로 정규화해서 해결(`cli.py`도 같은
  문제가 있어서 같이 고침)
