# 전체 폴더 구조 (계획)

`4_아키텍처_대화승인계층.svg` ~ `7_아키텍처_저장소_확장후_Postgres.svg`와 `진행상황.md`의
"다음에 정해야/만들어야 할 것" 순서를 코드 폴더로 미리 옮겨둔 것. 아직 설계가 안 끝난
영역(orchestration 내부, agent, db)은 껍데기 패키지만 만들어두고 실제 파일은 그 단계의
설계가 끝난 뒤에 채운다 — 지금 로직 없는 폴더를 미리 채우진 않는다.

`5_아키텍처_도메인저장계층_초안.svg` 이하 다이어그램들은 AccountService/CardService/
BillingService를 Orchestration 밑에 동급으로 그려둠 — 코드도 그대로 따라서
`account/`, `card/`, `billing/`을 서로 동급인 최상위 패키지로 둔다(Card를 account
안에 얹어두지 않음). account는 카드결제 거래내역을 보여줄 때만 `card` 패키지를
가져다 쓰고, 그 반대 방향 의존은 없다(card는 account를 모름 — account_id는 그냥 문자열).

## 의존 방향

기존 규칙 그대로 확장:

```
agent → orchestration → (account | card | billing) → 각자 repository → domain
```

- `orchestration`은 `account`/`card`/`billing`의 서비스 protocol만 알고 구현체는 모름 (생성자 주입)
- `agent`는 `orchestration`만 호출 — 도메인 서비스를 직접 호출하지 않음 (승인 없이 실행되는 경로를 원천 차단)
- `db.session`(PgSession)은 지금은 존재하지 않음 — Postgres로 옮길 때만 추가, 그 전까지 각 Memory 레포는 서로 독립

## 지금 만든 것

- `billing/`, `orchestration/`, `agent/`, `db/` — 빈 패키지(`__init__.py`만, 로직 없음)로 생성,
  각 `__init__.py`에 역할 한 줄 + 참고할 다이어그램 경로만 적어둠
- `card/` — account 안에 얹혀 있던 Card/ReissueRequest 도메인·repository·service를
  전부 이 패키지로 이동(account와 동급). `account/services/query.py`만 카드결제
  내역 표시를 위해 `card.domain`/`card.repository`를 가져다 씀

## 아직 안 정한 것 (각 단계 설계 시 다시 결정)

- billing: 기능 스펙 전달받아야 domain/repository/service 시그니처 확정 가능
- orchestration: `진행상황.md`의 미해결 질문 3개(소유권 검증 방식 / PendingRepo 스키마 / 재시작 복구 방식) 먼저 정할 것
- agent: LangGraph Tool 스키마·Context 주입 방식 미정
- db: Postgres 스키마·PgSession 트랜잭션 경계 미정
