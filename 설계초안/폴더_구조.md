## 의존 방향

기존 규칙 그대로 확장:

```
agent → orchestration → (account | card | billing) → 각자 repository → domain
```

- `orchestration`은 `account`/`card`/`billing`의 서비스 protocol만 알고 구현체는 모름 (생성자 주입)
- `agent`는 `orchestration`만 호출 — 도메인 서비스를 직접 호출하지 않음 (승인 없이 실행되는 경로를 원천 차단)
- `db.session`(PgSession)은 지금은 존재하지 않음 — Postgres로 옮길 때만 추가, 그 전까지 각 Memory 레포는 서로 독립

## 지금 만든 것

- `billing/`, `orchestration/`, `agent/`, `db/` — 빈 패키지(`__init__.py`만, 로직 없음)로 생성,
  각 `__init__.py`에 역할 한 줄 + 참고할 다이어그램 경로만 적어둠

  내역 표시를 위해 `card.domain`/`card.repository`를 가져다 씀

## 12. 저장 방식 정정 — Memory 다음은 JSON (Redis/Postgres보다 먼저) — 완료

당초 "PendingRepo는 지금 메모리, 나중에 Redis / 완료 이력은 Postgres"로 적어뒀던 걸
`오케스트레이션_설계.md`에서 고쳤다: 재시작 후에도 진행 중이던 업무를 찾고 승인 결과가
조회에도 반영돼야 해서, 순수 인메모리로는 안 되고 **지금 단계부터 JSON 파일 저장**이
필요했다. 그래서 저장소 단계가 하나 늘었고, 전부 구현 완료:

```
Memory (테스트용, 계속 유지) → JSON 파일 (지금 실제 동작 버전, 완료) → Redis/Postgres (확장 후)
```

`account`/`card`/`billing`/`orchestration` 전부 `*_repository_json.py`를 추가했다
(공용 `json_codec.py`/`json_file_store.py` 위에서 조립). Memory 버전은 안 없애고
테스트에서 계속 씀 — Protocol 기반이라 서비스 코드는 그대로 두고 생성자에 주입하는
구현체만 바꾸면 됨. 파일은 기본적으로 `data/*.json`에 생기고 `.gitignore`에 올려서
커밋 안 되게 해뒀음.
