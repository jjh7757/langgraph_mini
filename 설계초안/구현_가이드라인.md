# 계좌 이체 서비스 구현 가이드라인

`3_개선설계_서비스분리.png` 구조를 Python(3.13, `typing.Protocol` 기반)으로 옮길 때 참고할 가이드입니다.
코드는 직접 작성하시고, 여기서는 폴더 구조 / 순서 / 시그니처 / 결정해야 할 지점만 정리합니다.

## 1. 폴더 구조 제안

```
src/langgraph_mini/account/
    __init__.py
    domain.py          # Account, Transaction 도메인 모델 + 예외
    repository.py      # AccountRepository protocol + InMemory 구현체
    services/
        __init__.py
        query.py        # AccountQueryService
        transfer.py      # AccountTransferService
        manage.py         # AccountManageService

tests/
    test_domain.py
    test_repository.py
    test_query_service.py
    test_transfer_service.py
    test_manage_service.py
```

- 기존 `src/langgraph_mini/__init__.py`는 건드리지 말고, `account/`를 새 서브패키지로 추가하세요.
- DB 구현체(`SqlAccountRepository`)는 맨 마지막에 별도 파일(`repository_sql.py` 등)로 추가 — 처음부터 만들지 않습니다 (이유는 4절 참고).

## 2. 구현 순서 (권장)

1. **도메인 모델** (`domain.py`) — `Account`, `Transaction`, 예외 클래스
2. **AccountRepository protocol** (`repository.py`) — 메서드 시그니처만
3. **InMemoryAccountRepository** — protocol의 첫 구현체 (테스트/개발용)
4. **서비스 protocol 3개** (`services/*.py`) — Query / Transfer / Manage
5. **서비스 구현체 3개** — `AccountRepository`를 주입받아 씀
6. **테스트** — `InMemoryAccountRepository`를 그대로 주입해서 서비스 단위 테스트
7. (필요해지면) `SqlAccountRepository` 등 DB 구현체 추가

의존 방향은 항상 `services → repository → domain` 한 방향입니다. domain은 아무것도 import하지 않고, repository는 domain만 알고, service는 repository(protocol)만 압니다.

## 3. 왜 이 순서인가

- 아래에서 위로(domain → repository → service) 쌓아야 각 계층을 만들면서 바로 테스트할 수 있습니다.
- DB를 처음부터 붙이면 서비스 로직을 검증하기도 전에 커넥션/스키마 문제부터 마주치게 됩니다. `InMemoryAccountRepository`로 로직을 먼저 확정한 뒤 DB 구현체로 교체하세요 — protocol 덕분에 교체 비용이 거의 0입니다.

## 4. 컴포넌트별 시그니처 (로직은 직접 작성)

### `domain.py`

```python
from dataclasses import dataclass, field
from datetime import datetime


class InsufficientBalanceError(Exception): ...
class AccountNotFoundError(Exception): ...


@dataclass
class Account:
    id: str
    alias: str
    balance: int  # 원 단위 정수. float 금지 (반올림 오차 발생)

    def withdraw(self, amount: int) -> None:
        """잔액 < amount 면 InsufficientBalanceError.
        balance 필드는 이 메서드를 통해서만 바뀌어야 함 (직접 대입 금지)."""
        ...

    def deposit(self, amount: int) -> None:
        ...

    def rename(self, new_alias: str) -> None:
        ...


@dataclass
class Transaction:
    from_id: str
    to_id: str
    amount: int
    created_at: datetime = field(default_factory=datetime.now)
```

### `repository.py`

```python
from typing import Protocol
from .domain import Account


class AccountRepository(Protocol):
    def find_by_id(self, account_id: str) -> Account: ...
    def find_all(self) -> list[Account]: ...
    def save(self, account: Account) -> None: ...


class InMemoryAccountRepository:
    """AccountRepository를 상속하지 않아도 됨 — 메서드만 맞으면 protocol 만족."""
    def __init__(self) -> None:
        self._accounts: dict[str, Account] = {}

    def find_by_id(self, account_id: str) -> Account: ...
    def find_all(self) -> list[Account]: ...
    def save(self, account: Account) -> None: ...
```

### `services/query.py`

```python
from typing import Protocol
from ..domain import Account, Transaction
from ..repository import AccountRepository


class AccountQueryService(Protocol):
    def get_account(self, account_id: str) -> Account: ...
    def get_total_balance(self, account_ids: list[str]) -> int: ...
    def get_transactions(self, account_id: str) -> list[Transaction]: ...


class DefaultAccountQueryService:
    def __init__(self, repo: AccountRepository) -> None:
        self._repo = repo

    def get_account(self, account_id: str) -> Account: ...
    def get_total_balance(self, account_ids: list[str]) -> int: ...
    def get_transactions(self, account_id: str) -> list[Transaction]: ...
```

`services/transfer.py`, `services/manage.py`도 같은 패턴 (protocol + `Default...` 구현체, `repo: AccountRepository` 생성자 주입)으로 작성하시면 됩니다.

## 5. 코딩 시작 전에 먼저 정해야 할 것

이건 코드로 못 정하고 스펙으로 먼저 정해야 막히지 않습니다.

- **조건부 이체의 "조건"이 뭔가** — 잔액 기준? 예약 시각 기준? → `TransferCondition` 같은 값 객체를 먼저 설계
- **분할 이체가 일부만 실패하면?** — 전부 롤백(all-or-nothing) vs 성공한 것만 반영(best-effort) 중 하나를 정하기
- **이체의 원자성** — 출금과 입금 사이에 동시에 다른 요청이 끼어들면 어떻게 막을지 (`InMemoryAccountRepository`는 기본적으로 동시성 안전하지 않음 — 이번 범위에서 신경 쓸지 여부만이라도 결정)
- **거래 내역(Transaction) 저장 위치** — 지금 설계엔 `Transaction`을 저장하는 Repository가 없습니다. `get_transactions`를 실제로 구현하려면 `TransactionRepository`를 추가하거나 `AccountRepository`에 통합할지 정해야 합니다.

## 6. 체크리스트

- [ ] `Account.balance`를 서비스/외부에서 직접 대입하지 않고 `withdraw`/`deposit`으로만 변경
- [ ] 금액은 `int`(또는 `Decimal`) — `float` 사용 금지
- [ ] 서비스가 다른 서비스의 구현체를 import하지 않음 (protocol에만 의존)
- [ ] 서비스는 `AccountRepository` 구현체(`InMemoryAccountRepository` 등)를 직접 알지 못하고 항상 생성자로 주입받음
- [ ] 서비스 테스트는 mock 없이 `InMemoryAccountRepository` 실제 객체로 진행
